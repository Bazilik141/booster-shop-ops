## Порядок робіт

### Крок 0 — підготовка
1. Переконатися, що `boostershop-ds.css` з основного аудит-пакета вже задеплоєний (Phase 0 в `handoff/HANDOFF.md`).
2. Відкрити локально `Контентні сторінки редизайн.html` — це візуальна правда (ground truth) для всіх шести сторінок.

### Крок 1 — CSS
1. Скопіювати вміст `content-pages.css` у кінець `boostershop-ds.css` (або підключити окремим файлом `boostershop-content.css` поруч).
2. Звірити, що нові змінні не конфліктують зі стилями теми. Усі класи мають префікс `.bs-cp-`.

### Крок 2 — Twig шаблони
1. Замінити `catalog/view/template/<theme>/information/information.twig` на `templates/information.twig` з цього пакета.
2. Замінити `catalog/view/template/<theme>/checkout/success.twig` на `templates/checkout-success.twig`.
3. У контролері `catalog/controller/checkout/success.php` додати передачу даних замовлення (`order_id`, `items`, `total`, `shipping_method`, `payment_method`, `history_url`) — приклади дивись в `templates/checkout-success.twig`. Зараз контролер передає тільки `text_message`; треба розширити.

### Крок 3 — текстова ревізія (КРИТИЧНО)
1. Відкрити `text-revision-tasks.md`.
2. **Пройти всі задачі по черзі.** Для сторінок 5 (Обмін) і 6 (Оферта) — обов'язково витягнути актуальний текст з бойового сайту (зараз там стоїть драфт-плейсхолдер) і перенести його в новий формат.
3. Для решти — звірити з останньою редакцією на бойовому сайті, перевірити юридичну точність і узгодити з власником.

### Крок 4 — наповнення сторінок
1. Зайти в адмінку → Каталог → Інформація.
2. Для кожної з 5 інфо-сторінок (Гарантія, Про нас, Оплата, Повернення, Оферта) — вставити вміст відповідного `content/0X-*.html` файла у поле «Опис» **у режимі HTML** (не WYSIWYG, бо TinyMCE може поламати кастомні класи).
3. Перевірити, що заголовок сторінки в адмінці залишається в полі «Заголовок» (він рендериться в Hero шаблоном, не дублюється в описі).

### Крок 5 — QA
Дивись QA-чек у `text-revision-tasks.md` в кінці.

## Дизайн-патерни (короткий конспект)

Якщо потрібно додати нову контентну сторінку в тому ж стилі:

- **Hero-картка:** обгортка з лівою вертикальною смугою 4px (`.bs-cp-hero__stripe--gold|blue|green|ink`), всередині — eyebrow «Booster Shop» + `<h1>` + lede + іконка справа (опціонально).
- **Eyebrow:** мала JetBrains Mono-підкреслка `01`, `02` для пронумерованих секцій.
- **TOC:** sticky, ховається ≤900px.
- **Callout:** 4 тони (`blue|gold|green|grey`), іконка зліва.
- **Telegram CTA:** обов'язковий футер кожної сторінки.
- **Зелений CTA — тільки на «Замовлення прийнято».** На решті — синій outline.

## Що НЕ робити

- ❌ Не переписувати inline-стилі з JSX у CSS буквально. У React mock'ах є inline-стилі через зручність — для прода використовувати готові класи з `content-pages.css`.
- ❌ Не змінювати порядок чи назви класів `.bs-cp-*` без узгодження — на них зав'язана адмінка.
- ❌ Не публікувати оферту з плейсхолдерними реквізитами (`0000000000`, `UA00 0000…`). Замінити на реальні дані ФОП Леусенко Євгеній Андрійович.
- ❌ Не заливати тексти зі сторінок 5 і 6 без юридичної перевірки.
