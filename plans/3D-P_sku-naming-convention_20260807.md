# 3D-P — канонічна конвенція артикулів (SKU) і назв товару

Date: 2026-08-07 | Автор: Claude (chat), затверджено власником у діалозі
Джерело історії: `plans/3D-P-002_catalog-placement-admin-guide_20260731.md` §8 (оригінальна 3-префіксна конвенція, 2026-07-31) + `3d-print/3D-P_nomenclature-tracker_v6_20260731.xlsx` (вкладка «Легенда», той самий запис) + сьогоднішнє розширення під варіативність (колір/розмір).

**Це канонічний документ для SKU/артикулів 3D-друкованої продукції.** Коли `3d-print/3D-P_nomenclature-tracker` оновиться до v7+, перенести цю легенду туди дослівно — цей файл лишається джерелом правди до того моменту.

## Формула

```
<ПРЕФІКС>-<МНЕМОНІКА>-<XYZ>
```

- **ПРЕФІКС** — тип виробу за оригінальною конвенцією 31.07: `BR-` (брелок/підвіска), `FIG-` (самостійна фігурка), `ACC-3D-` (функціональний аксесуар). Незмінно, не займати.
- **МНЕМОНІКА** — короткий код персонажа/теми, **не більше 5 символів**, читабельний. Дропати голосні/зайві літери, а не обрізати довільно (приклад: `JIGGLYPUFF` → `JIGGL`, не `JIGGL` навмання — лишати впізнавану частину).
- **XYZ** — три цифри, кожна свій рівень:
  - **X (сотні)** — категорія в межах префікса (див. легенди нижче). Розряди кратні 10 (100, 200, 300…) — категорії НЕ повинні бути сусідніми числами (не 200/210), кожна нова категорія — нова сотня.
  - **Y (десятки)** — підтип/модель у межах категорії (напр. розмір-лінійка «мала/середня/велика» → 1/2/3; колір-група → 0/1).
  - **Z (одиниці)** — варіант у межах підтипу (розмір M/L, колір, сумісність бренду тощо). За замовчуванням `0`, якщо варіантів поки немає.

Приклад: `ACC-3D-PKM-130` = функціональний аксесуар, тема Pokémon generic, категорія 1 (підставка для карток), підтип 3 (велика), варіант 0 (немає доп. варіанту).

## Легенда — FIG- (категорія, сотні)

| X__ | Категорія |
|---|---|
| `1__` | Фігурка-в-покеболі / капсула-тип |
| `2__` | Статична декоративна фігурка |
| `3__` | Модель-кіт на литнику (збірна плата, «Пластини» в файлі Сергія — сюди) |
| `4__` | Пласка настінна форма (силует / панно / картина) |
| `5__` | Рухома (wobble) фігурка |

## Легенда — BR- (категорія, сотні)

| X__ | Категорія |
|---|---|
| `1__` | Звичайний брелок-підвіска |
| `2__` | Брелок-клікер (fidget) |
| `3__` | Набір брелоків (кілька виробів в одному товарі) |

## Легенда — ACC-3D- (категорія, сотні)

| X__ | Категорія |
|---|---|
| `1__` | Підставка для карток |
| `2__` | Підставка під грейджені слаби, без покебола |
| `3__` | Підставка під грейджені слаби, на ніжці |
| `4__` | Побутовий аксесуар (стакан, цукерниця, підставка під телефон тощо) |
| `5__` | Світильник |
| `6__` | Пласкі пластикові аксесуари (закладки тощо — уточнено: закладка теж пластикова, не паперова) |

`ACC-3D-` зберігає окрему нумерацію від класичного `ACC-0XX` (не-3D аксесуари, `plans/accessories_sku_cards_20260620.md`).

## Мнемоніки, вже використані (≤5 символів)

`CHARM`, `DITTO`, `ONIX`, `MEW`, `LUFFY`, `GEOD` (Geodude), `JIGGL` (Jigglypuff), `UMBRE` (Umbreon), `PKBL` (Pokéball-як-персонаж), `OPMUS` (One Piece, капелюх-вуса), `OPSTR` (капелюх-солома), `OPFRT` (фрукт), `OPSKL` (череп), `OP` (One Piece, загальна тема без конкретного персонажа), `PKM` (Pokémon, загальна тема без конкретного персонажа).

## Формула назви товару (SEO)

```
{Тип виробу} {Персонаж/Тема} ({Франшиза})[, {варіант}] — 3D-друк
```

Зразок-прецедент (затверджений раніше, `3D-P-002`): «Брелок Чармандер (Pokémon) — 3D-друк».

- **{Тип виробу}** — людський відповідник категорії SKU (сотні), див. таблицю нижче.
- **{Персонаж/Тема}** — повне ім'я українською, не мнемоніка з SKU.
- **({Франшиза})** — `(Pokémon)` / `(One Piece)`, **у дужках, після персонажа, не на початку назви.** Це свідоме рішення, не стилістика: назва товару в позиції «Франшиза + Тип + Персонаж» (напр. «Pokémon Фігурка Онікс…») граматично мімікрує під офіційне ліцензійне найменування («Pokémon Trading Card Game», «Pokémon Center …») і підвищує ризик сприйняття як заяви про офіційність/партнерство — це прямо суперечить п. 7.8 чинної оферти («не є офіційною продукцією відповідних правовласників... не свідчать про партнерство чи афілійованість»). Франшиза в дужках після описової частини — номінативне (описове) використання, нижчий ризик. Власник підтвердив 2026-08-07.
- **[, {варіант}]** — розмір/колір/механіка, лише якщо реально відрізняє цей SKU від інших SKU того самого персонажа (не дублювати те, що й так не варіюється в межах персонажа). Реальні см — не вигадувати, `{{розмір}}` лишається плейсхолдером до заміру власника.
- **— 3D-друк** — фіксований суфікс, не змінювати.

## Відкриті пункти (не блокують сьогоднішню партію)

- **Легасі-резерви `ACC-3D-001/002/003`** (з `3D-P-002` §8, 31.07: Кейс-покебол «Мяу», Підставка-олівниця «Дітто», Дек-бокс «Покебол») — жоден ще не надрукований, не входять у сьогоднішню printable-партію. Схоже, «Підставка-олівниця Дітто» відповідає позиції «Стакан під ручки Дітто» в новому файлі Сергія (там статус «Ні», поки не друкується). Коли ці три стануть реальними — потрібні нові категорії в легенді ACC-3D- (напр. `7__` кейс/контейнер, `8__` дек-бокс), зараз не додаю, бо немає підтвердженого товару під них.
- **`threeDpSkuTypeError` (dashboard) і `apiAddSale_` (головна CRM)** — живий код зараз валідує SKU за старішим, вужчим регексом (без підтримки суфіксів/трицифрової структури для `ACC-3D-`). Ця розбіжність свідома: власник підтвердив, що зона 3D-P-010/013 буде переписана майже з нуля, тож цей документ — canonical-джерело для НОВОГО regex/легенди, коли та переробка стартує. До того — SKU з цього документа використовуються лише в Номенклатурі/картках товару, не заводяться в SKU, що йдуть через головну CRM-тригер логіку, яка ще не відповідає цій структурі.
- **Формула назв товару (SEO)** — окремий крок, ще не узгоджено.
