## 3. Колізії `seo_url` — **немає жодної**

### 3.1 Як насправді працює SEO URL категорії (важливо для формату ключа)

`catalog/model/design/seo_url.php::getSeoUrlByKeyword()`:

```sql
SELECT DISTINCT * FROM ocp5_seo_url
WHERE (`keyword` = '<part>' OR `keyword` LIKE '%/<part>') AND `store_id` = 0
LIMIT 1
```

`catalog/controller/startup/seo_url.php` ріже `_route_` по `/` і шукає кожен
сегмент окремо. Тому для підкатегорії в `keyword` зберігається **повний шлях**,
а не голий слаг. Живі рядки це підтверджують:

```
(996,0,4,'path','66_65','more-tcg/Yu-Gi-Oh',0)
(1027,0,4,'path','59_62','Pokemon/Pokemon-booster-box',0)
(1073,0,4,'path','60_63','One-Piece/One-Piece-Boosters',0)
(1173,0,4,'path','70','acsesuary',0)
```

⚠ **Це не те, що написано в хендофі.** Розділ 5 подає `SEO URL` як
`protektory-ta-zberihannia`. Якщо записати саме цей рядок у `keyword`, сторінка
відкриється як `/catalog/protektory-ta-zberihannia` **без сегмента батька**, і
хлібні крихти в URL зникнуть — на відміну від усіх наявних підкатегорій.
Патч записує повний шлях; слаг із хендофу використано як останній сегмент.

| Категорія | `key` | `value` | `keyword` (фактичний запис) |

## 7. Спосіб внесення і потреба в SQL-відкаті

**Внесення робиться патчем, не руками.** Обсяг — 4 категорії, 9 перенесень,
6 атрибутів, 19 товарів із 13 атрибутами кожен (247 рядків `product_attribute`),
плюс `seo_url`, `product_code`, `product_to_store`, `product_to_category`,
`category_path`, `category_to_store`. Ручне внесення такого обсягу в адмінці
дає передбачувану помилку набору в текстах, які узгоджені дослівно.

**Отже SQL-відкат потрібен** (розділ 7.1, п. 2–3 хендофу).

Кожен патч:

1. пише фактично призначені auto-increment ID у
   `_patch_backups/<patch>-<ts>/db/created_ids.json`;
2. пише повний зліпок «до» у `…/db/<scope>_before.json`;
3. несе rollback SQL у шапці файлу з посиланням на ці ID.

### 7.1 Очікувані ID (за станом бекапу — фактичні пише сам патч)

За `AUTO_INCREMENT` на момент бекапу, **якщо між бекапом і запуском нічого не
створювалося**:

| Об'єкт | Очікувані ID |
|---|---|
| Категорії | `71`, `72`, `73`, `74` |
| Атрибути | `50`–`55` |
| Товари (брелоки) | `125`–`129` |
| Товари (фігурки + підставки) | `130`–`143` |

⚠ **Ці числа не захардкоджені в патчах.** Патчі читають `insert_id` і пишуть
фактичні значення у `created_ids.json`; відкат робиться саме за ним. Числа вище
— орієнтир для власника, а не контракт.

### 7.2 Rollback за замовчуванням, без SQL

- Категорії: створюються порожніми, вимикаються одним прапорцем `status`.
- Перенесення товарів: оборотне через адмінку —
  `UPDATE ocp5_product_to_category SET category_id = 70 WHERE product_id IN (95,96,97,98,99,100,112,113,114)`.
- Атрибути: жодному товару не призначені до P3/P4.
- Товари: створюються `status = 0`, тобто невидимі; видалення — за
  `created_ids.json`.
