# Codex Report — R-13.5: mini-cart checkout refresh

Date: 2026-07-25

## Scope

Owner QA confirmed that mini-cart quantity/removal requests mutate the OpenCart
cart session and mini-cart correctly, but the stock checkout keeps its stale
items, totals, shipping state, and payment gates until F5.

The patch emits a checkout-scoped event only after a successful mini-cart
mutation. The existing checkout state coordinator then invalidates stale
shipping/payment state and re-runs the authoritative server sequence:

```text
shipping quote -> shipping save -> rendered summary -> payment methods
```

- `booster-debug-R135-cart-refresh.tar.gz`
- SHA256: `0998fc1e0e2e3165707b7db57613f3a196b47305feebb804123513632a2c7ccb`

No DB, order-write, coupon calculation, payment-provider, or external API logic
is changed.

## Side effects / risks

- A successful cart mutation intentionally clears stale shipping/payment
  selection and lets the existing server coordinator select currently valid
  methods again.
- Scope is the mini-cart quantity/remove controls supplied in the live archive.
- No DB or order lifecycle changes.
