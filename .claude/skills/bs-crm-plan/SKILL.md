# Booster Shop — CRM / Automation Read-only Planner

## When to use
Use when owner wants a new report, dashboard view, import or automation on top of Booster Shop CRM or master dashboard.

Master dashboard:
`1YUGdtxHQJee6vY8MdwRsrUxudJCMtnghOGPVJXwO5ik`

## Hard rules
- CRM is read-only by default
- No write-back to CRM or OpenCart without explicit owner approval
- Never change formulas in master dashboard
- Never run CRM cleanup automatically
- Do not duplicate manual workflow without checking source of truth first
- Sequence:
  `read → import → dashboard / report → automation`
- Automation only after owner approval
- Automation only after read pipeline is stable for 2+ weeks

## Output format
1. What to read — sheets / ranges / frequency
2. What not to touch — formulas / filters / roadmap A:L / manual CRM columns
3. Report / dashboard to build — separate sheet or table (read-only)
4. Derived fields — calculated without writing to source
5. Coupling with manual workflow — overlap / duplication risks
6. Automation roadmap — phases + approval gates
7. QA checklist

## Acceptance criteria
- No write actions planned without explicit approval gate
- Master dashboard formulas marked as read-only dependencies
- Clear source of truth for each metric
- Clear note on what stays manual and why

## QA checklist
- [ ] No write actions in CRM / OpenCart / master dashboard formulas
- [ ] Source of truth listed for each metric
- [ ] Manual workflow overlap clearly identified
- [ ] Duplication risk noted if present
- [ ] Automation delayed behind `read-pipeline stable 2+ weeks`

## Risks
- Double accounting → conflicting data
- Apps Script race condition with manual entry
- Hidden overwrite of CRM data
- Loss of trust in dashboard metrics

## Mitigation
- One source of truth per metric
- Derived views only
- Separate automation output tabs
- Explicit owner approval per write action
