# Booster Shop — SEO Risk Gate

## When to use
Before any SEO or technical SEO task.

Auto-run as preflight before `bs-codex-handoff` if task tags include SEO / technical / structure.

## Risk classification

### High-risk (owner approval + staging first)
- `sitemap.xml`
- `robots.txt`
- redirects (301/302, `.htaccess`, server rules, OpenCart redirect rules)
- canonical
- noindex / x-robots-tag
- schema (JSON-LD / microdata)
- Merchant feed (XML / CSV / TSV)
- checkout / payment URLs
- hreflang
- pagination / rel-prev/next

### Medium-risk
- bulk title / meta description updates (>10 pages)
- internal linking restructure
- URL slug changes without redirects → auto High-risk
- structured data on new page types

### Low-risk
- alt text
- body content
- on-page copy without URL/title changes

## Output format
1. Risk: High / Medium / Low
2. Affected assets: files / URL patterns / page types
3. Do not touch
4. Safest next action
5. QA checklist
6. Owner approval required: yes / no
7. Related smoke checks (`bs-checkout-smoke`, `bs-merchant-schema-qa`) if relevant

## Hard rules
- Any canonical / redirect / sitemap change → staging + before/after fetch required
- Any URL slug change → auto High-risk + 301 required
- Merchant feed touched → add `bs-merchant-schema-qa`
- Classify by affected assets, not by size of change

## Acceptance criteria
- Risk tied to specific assets
- High-risk includes staging + rollback plan
- Owner approval clearly stated

## QA checklist
- [ ] sitemap / robots / canonical checked
- [ ] Merchant feed checked
- [ ] URL changes / redirects checked
- [ ] checkout / payment URLs checked
- [ ] owner approval gate noted if High-risk

## Risks
- Missed High-risk → deindexing / Merchant drop
- Hidden side effects across page types → explicitly list all affected assets
