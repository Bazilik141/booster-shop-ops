# Booster Shop — Checkout / Payment Smoke-Test Builder

## When to use
Use for any task touching:
- checkout
- payment
- coupons
- fiscalization
- order status
- success redirect
- purchase flow

## Mandatory test set: 11 steps

1. Register → Checkout  
   New user signup, add item to cart, proceed to checkout.

2. Auto First15  
   `First15` auto-applies on first order for new user.

3. Manual First15 reuse  
   Same user tries to reuse `First15`; reuse must be blocked.

4. Invalid coupon  
   Invalid code shows clear error, does not break checkout, no duplicate errors.

5. Nova Poshta data  
   City + branch selection, required field validation, fallback if API unavailable.

6. Order button visibility  
   `Оформити` button visible/enabled only when required fields are valid.

7. Hutko payment return / session  
   Return from provider works, session stays alive, order status is correct: paid / failed / pending.

8. Success redirect  
   User lands on success URL with correct `order_id`; success page renders.

9. Clean JSON responses  
   AJAX endpoints return valid JSON only, no PHP warnings/notices/HTML.

10. Email delivery  
   Order confirmation reaches test inbox; order links work.

11. Checkbox / fiscalization  
   If payment/status was touched, verify receipt in sandbox/staging.

## Output format
Use Markdown table:

| # | Test | Steps | Expected | Actual | Pass/Fail |

After table include:
- Final summary: pass count / total, blockers, recommended status
- Sandbox / staging notes

## Hard rules
- Owner or staging tester runs the smoke test
- Claude/Codex never execute real payments
- Use Hutko sandbox if real flow is not safe
- Fiscalization logs only in staging
- If any of 11 steps cannot be run, mark `n/a` with reason
- No automatic actions on real orders

## Acceptance criteria
- All 11 steps included or marked `n/a`
- Tests are staging / sandbox only
- Every step has a concrete expected result
- No real payment suggested

## QA checklist
- [ ] All 11 steps included
- [ ] Every step has expected result
- [ ] Staging/sandbox environment stated
- [ ] Checklist ready for manual run
- [ ] No real payment suggested

## Risks
- Broken checkout → direct revenue loss
- Fiscalization fail → legal/accounting risk
- Coupon reuse exploit → margin loss
- Dirty JSON response → checkout/AJAX failure

## Mitigation
- Smoke test before production deploy
- Separate fiscalization gate before production
- Run First15 tests 2 and 3 together
- Check JSON endpoints for clean responses
